# DC3DD 原版系统接入进度（0.4.0-ui-dev）

这次修改执行现有游戏的系统脚本，没有改写 MES、重做标题图片或在 Android 中写死角色选择界面。
当前是原版系统兼容的第一阶段，**不是完整 DC3DD 兼容版，也不能运行 DC2DM**。

## 已接入

- 正常入口为 `START → WIN_SIZE → MAIN`，包括原脚本安排的启动画面、影片与标题动画。
- `MAIN` 的原版标题、`SCESELECT` 的角色列表和角色介绍、EXTRA 第一层菜单。
- 原版退出确认框及取消、确认退出；“不再确认”的勾选图块与成对记忆标志按原生规则处理。
- 按钮热区、图块裁切、普通／悬停／按下状态、音效与标签动作来自原 MES。
- 触摸在统一的 1024×576 逻辑坐标上命中按钮，释放后由 VM 查找原始字节标签。
- Android 返回键在菜单等待中映射到脚本注册的右键动作；没有注册时退出 Activity。
- 原版模式执行返回 `MAIN` 的脚本转移，不再截获成 Android 标题页。
- `Dc3Ui` 保留原版面板模板、动作、按钮状态及元数据；快照保存菜单等待和事件代次。
- 启动器只显示选目录与启动游戏。旧路线直达、存档及正文演出审计仍作为独立开发工具保留。
- APK 图标使用用户于本轮提供的蓝色 D.C. 樱花图；自适应图标通过资源布局留出裁切空间，源码中的原 PNG 未修改；APK 资源打包后像素逐点相同，并已检查 Android 应用列表中的显示。

`0.4` 新的原版模式快照与 `0.3` 剧情审计快照分开校验；不会把旧剧情快照当成完整原版系统状态。

## 可复用的实现

`MesVm.MenuHost` 只负责取得动作字节、校验事件代次、解析标签与恢复执行，不含任何角色或路线名。
`Dc3Ui` 提供面板、矩形按钮和状态图块模型；`Dc3Host` 将 DD 版本的指令绑定到该模型。
Android 仅负责绘图和输入。其他版本仍需独立核对 opcode、模板选择表、特殊变量与宿主行为，不能仅换一个 profile 名称就宣称兼容。

| 指令 | 已接入的规则 | 原生静态依据 |
| --- | --- | --- |
| `5E` | 版本字符串 | `42AE56` |
| `3B` | 系统资源槽 36–40 | `42B331` |
| `19` / `23` | 清理、保存 UI 面板；保留原生选择表 | `42B3C6` / `42D63B` |
| `6C` + 后续字符串 | 注册热区与动作；不立即执行其标签 | `42B4DD → 417530` |
| `16` | 悬停和点击音效 | `42B738 → 412FD0` |
| `6D` + `71` | 图集裁切与按钮状态 99／1／2 | `42B56E → 417A10` |
| `74` / `82` | 静态图块和 UI 原点 | `42D7AB → 4176B0` / `412E50` |
| `0B` | 菜单等待，不直接落入后面的标签 | `42BB1C` |
| `41` | 脚本动作注册；已使用右键动作 | `43033F` |
| `48` | 系统语音通道 | `4300BA` |
| `73` / `55` | 确认框原点、模板 12 和按序号选择的提示图块；Yes/No 跳到动作槽 0/1 | `430678` / `430571` / `417E20` |
| `1D [18,*]` | 设置备份、忽略当前页签的变更比较、尚未提交时回滚 | `40A4E9`–`40A5F4` |
| `10` | 原退出脚本结束游戏 Activity | `42AF48` |
| `8B` / `26` / `66` 独立分发 | 经确认的原生空分支 | `431CC2` |

`70` / `81` 的附属字符串、`75` 文字样式、导航标志等仅有元数据接入。
**活动面板需要尚未实现的文字绘制或动态表面时明确停止，不把空画面算作成功。**
`85` 继续使用既有的立绘变换语义，不能误当成背景定位。

背景替换会通过 `42E3B7 → 441E00 → 441AF0` 重置背景渲染对象。此前标题滚动的 y=-576
残留到下一张背景导致黑底，现已修复，并有合成测试覆盖。

启动音频包含 XPCM mode 3 的零频谱数据。当前严格检查 zlib、完整块数、参数及全部频谱为零后，
输出精确的零样本 PCM；没有文件名特判。非零 mode 3 和 mode 1 仍不支持。
此子集依据已有 GARbro `AudioPCM.cs` 参考：有符号查表的输入零映射为零，随后整数逆变换、重叠与裁切保持零。

原生证据锁定 `DC3DD.EXE` SHA-256：
`ff119f4396cc1382e349fb1ed2c2eb77191db8ec699cb1352ca021cc73407e8d`。
用 `tools/capture_system_ui_evidence.py` 可重新导出这些静态范围；工具只读取 PE 文件。

设置备份只覆盖原生前 `0x4b74` 内在当前状态模型中已表示的字段，不复制普通脚本变量或活动选择。
比较时临时忽略 `100:54`（设置页签），将差异结果写入 `3:0`；比较完成后取消回滚状态。
Android 将窗口状态查询 `99:4` 映射为当前全屏模式。设置保存到磁盘、音量变化等仍需完整接入。
`1D [20,非零]` 对应释放缩略图缓存；当前宿主尚未分配此缓存，释放为空操作，未把加载缩略图分支当作支持。

确认框从原模板的匿名按钮取第一张普通背景和第 N 张提示图块；有动作的按钮保留原三态和音效。
`:y`、`:n` 分别解析脚本动作槽 0/1；`:c` 更新 bank 93，并遵循原生 1↔2、4↔9、5↔10 配对。
勾选图块独立于悬停态绘制，Android 返回键执行取消动作。记忆标志当前可随内存状态和快照保存，尚未跨应用启动持久化。

## 验证与边界

- 桌面 JVM 与 Android ART 都通过 157 个自编合成断言，包括菜单快照、标签跳转、过期触摸拒绝、按钮三态、背景位移重置、设置事务、原模板确认框与压缩静音的反例检查。
- 34 个 Python 静态解析测试。
- JVM 从原版启动脚本进入标题，并从原版角色选择逐一进入七条路线的首段正文；相关图像与音频实际解码。
- 旧剧情审计的 14 条终局路径回归通过（默认状态、固定 RNG；媒体完成在流程审计中模拟）。
- Android ART 执行原启动脚本至标题；`MenuInstrumentation` 从该真实执行生成的快照验证实际 View 触摸、按下态、角色介绍、返回标题及 EXTRA 往返，保存截图。该项启动媒体完成是模拟的，不能替代实际影片播放测试。
- 原确认框取消、勾选及取消勾选、执行退出脚本均有 JVM 与 Android 触摸验证；图片为 `12-confirm-exit.png`、`14-confirm-checked.png`、`13-confirm-cancel.png`。
- 另外从 Android 启动器实际启动 START，真实播放片头影片至结束，再进入原版标题；截图为 `build/original-ui/07-real-start.png`、`08-real-start-progress.png`、`09-real-title.png`。
- 本轮没有启动 Windows 游戏程序。原游戏目录保持只读。

已经定位但尚未实现的原版系统入口：

| 操作 | 当前首个停止点 |
| --- | --- |
| CONFIG | `CONFIG @0xC5D`，`6D+71` 的模式 5 滑动条范围和变量绑定；已定位 `412F70`，尚未执行 |
| LOAD | `LOAD @0x331`，`77` 存档页面动态内容 |
| GAME END | 已贯通确认、退出语音、淡出和 `MAIN @0x3DEF` 的退出指令 |

这些只是各路径的第一个缺口。后续还包括系统文字、滑动条、存档缩略图、内置冒号动作、鉴赏子页面、
设置持久化、原版正文框和选择框。当前正文呈现仍沿用旧剧情播放器，不能当成已恢复原版正文 UI。
原版模式暂不开放旧 Android 替代存读档操作，存读档功能必须随原版脚本界面一起接通。
