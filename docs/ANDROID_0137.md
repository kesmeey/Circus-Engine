# Android 0.13.7：DC3R 序章白屏等待修复

安装 `build/distribution/circus-runtime-0.13.7-android-dev.apk`，可覆盖安装；游戏目录、解释器存档和设置无需重建。本次针对 `dc3r-unity-550`，未改变原脚本、转场时长或存档格式。

## 原因与修复

本机 `Da Capo 3R X-Rated` 的原脚本从标题选择 Start、序章后，先在 `dc3_1_0222_e1_pro:145` 显示白色转场，再在指令 236 加载背景及立绘。其间没有等待语音完成的指令。

查找立绘时，要依次在多个资源包查询名称。没有匹配的容器别名时，原实现逐个读取对象名；前三个立绘包的首次索引触发数千次 Android 文档提供器文件打开。渲染与音频启动回调共用工作线程，因此等待期间会表现为白屏且无声。

现在索引一次资源包时复用一个只读句柄，结束或异常时关闭；相邻对象头按不超过 256 KiB 的范围读取。原版立绘包中的对象之间常有很大的图片数据间隔，不会为了合并读取而扫描这些大段像素。

容器路径、自定义对象名、资源覆盖顺序、重复名称判定保持原行为；未把所有未命中直接视为不存在。读取边界与解码校验保留。没有在手机上解包整部游戏，也没有常驻大尺寸解码缓存。

## 验证

只读计数针对本机完整原资源：

| 范围 | 修复前文件打开 | 修复后文件打开 |
| --- | ---: | ---: |
| 序章指令 236 的首次画面加载 | 7,434 | 317 |
| START 至第一句对白 | 9,286 | 835 |

Android 35 模拟器使用真实 DocumentTree / SAF 接口及原资源稀疏测试副本，经过 Activity 帧时钟、触摸和 MediaPlayer 回调，未手动增加 VM 时间或模拟音频完成：

- 选择序章至第一句对白：36,961 ms → 9,102 ms。
- 白屏状态 145 至画面加载状态 236 的观察间隔：31,522 ms → 3,635 ms。
- 原片头标志影片正常通过平台播放器；随后连续推进五个对白等待点。

这些是同一模拟器上的单次对照，包括原脚本自带的等待和测试观察开销，不是手机耗时保证。测试副本仅复制记录过的原资源范围，未将整部游戏复制到模拟器；完整原文件另通过桌面解释器验证。测试数据不会随源码或 APK 分发。

最终 APK 通过 879 项 JVM 与 Android ART 核心断言、7 项 Canvas 像素契约和 484 项转场像素比较。新增资源测试覆盖句柄复用、异常关闭、名称回退、容器不完整、读取上限及歧义拒绝。
完整原资源的 70 句对白与 62 项系统流程检查通过，包含保存、读取、设置、回看和鉴赏页面；四张关键画面与修复前逐像素一致。尚未验证 DC3R 的全部路线。

本地证据在 `build/dc3r-white-0137/`、`build/dc3r-white-audit/regression-summary-final.json` 和 `build/dc3r-white-audit/io/`。

## DC3R 原版存档导入范围

本版本仍不支持导入 DC3R Unity 的 PC 系统进度或剧情槽位；解释器内新建的存档可以保存和读取。启动器对此版本显示专用说明。

此 PC 版本通过原程序的 `CHelper.ConvertToSavePath` 使用 `%APPDATA%\Mangagamer\DaCapo3R`，不是游戏文件夹：

- `global.dat`：系统进度和设置。
- `save000.dat` 至 `save101.dat`：剧情槽位。

原格式使用 4 字节小端长度前缀加 protobuf，与手机解释器的 Unity 持久化格式、以及 DCPC／DC2PC／DC2DM／DC3DD 的 `system.dat` 均不同，不能复制改名代替转换。
已只读确认本机的原存档与序列化代码，但本机样本没有 CG／场景通关记录；本次没有新增未经验证的导入转换。此前四款 MES 游戏的原版系统进度导入继续保留。
