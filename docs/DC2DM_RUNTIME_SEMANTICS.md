# DC2DM 语义记录

0.5.0 已在下列静态基础上接入原版系统与剧情宿主，最新运行范围、原生地址和验证方法见 [DC2DM_PLAYBACK.md](DC2DM_PLAYBACK.md)。以下为 0.4.1 历史记录，不能作为当前 APK 状态。

## 0.4.1 静态基线

本轮完成的是共用核心的 DC2DM 版本绑定，**不是 DC2DM 可玩版**。没有运行 Windows 游戏，没有修改原游戏目录。

资源层抽出 `CircusResources`，脚本版本由调用方显式传入；`Dc3Resources` 仅保留为旧 DD 审计入口的兼容包装。
Android 用整套 MES 的版本候选交集识别目录，不再把所有目录直接交给 DD 解析器。混入其他版本或未知版本的脚本会拒绝启动。
26 份格式表用于识别，只有已核对的语义表可创建解释器；识别成功不表示该作的系统宿主已实现。

## 不可沿用 DD 的规则

| 行为 | DC2DM |
|---|---|
| 普通字节写入 | 夹限到 0～255；DD 的低 8 位截断规则不适用 |
| 200～210 银行 | 普通变量连续四字节的大端有符号 32 位视图，起始索引至 96 |
| 300～310 银行 | 普通变量连续两字节的大端有符号 16 位视图；写入夹限；起始索引至 98 |
| 100 银行 | 写入索引 0～99，保留低 8 位；0～20 与普通银行 10 互相映射 |
| 400 银行 | 100 银行的大端有符号 16 位视图；索引 99 写入时只有高字节生效 |
| 96／97／98 银行 | 分别为 400／1200／650 个位标志，不是独立字节数组 |
| 文本解码 | 加 32 后保留 `$`；不能套用 DD 的 `$`→空格替换 |
| 62 模式 3 | `99:255 = read(p2, read(p0,p1))` |
| 3D 跳转 | 空标签或缺失标签进入错误；不能静默忽略，也不能寻找 00 后的标签 |
| 1D 块跳过 | 参数 p1 为无符号字节，扫描目标的标记字节有符号；与条件伴随指令的有符号 ID 不同 |

`Dc2State` 保留持久内存的连续布局，因此 `100:100` 的读取能观察音乐标志首字节，`400:99` 的低字节也能观察该字节。
这类边界行为有单独测试。负索引和超出已核对内存范围的读取会安全报错，不复制原生越界行为。
未核对的 99 银行系统查询和写入效果会报错；没有用全零数组伪造窗口、声音或 UI 状态。
持久变量写入只标记待保存，尚未连接 DM 的原版系统保存流程。

## 已验证范围

- JVM 与 Android 使用同一套核心测试；共 196 个断言，包含 39 个新的 DM／版本识别反例。
- Python 静态工具 38 项测试。
- 原版 311 个 MES，共 376,130 条物理记录通过解析；40,472 个头部偏移均落在指令边界。
- 14,188 条条件记录、4,581 条直接跳转的静态分析无结构问题；这是潜在控制流检查，不是实际走完剧情。
- Java 共用资源接口成功读取 DM 的 NAMES 与原版 `SYSTEM/ADVMENU_CHIP`，解码为 775×1000、32 位图像。
- DD 原版 `START → WIN_SIZE → MAIN` 回归仍可到达五按钮标题菜单。

本轮绑定了 15 个指令编号及其复合操作。全体脚本仍有 237,341 条物理记录未绑定语义；不得把上述结构检查说成游戏已经可以运行。

## 接下来必须实现的宿主部分

1. DM 原版 UI 使用独立的绘图片段列表（21）和按钮列表（17）。两者有不同的模板目的地址、容量和清空规则，不能直接套用 `Dc3Ui.store()`。
2. START 在载入 UI 图片之前就定义了部分片段；需要保留原生资源槽引用，使用时再解析，不能在建模时把空槽永久变成空图片。
3. 核对 UI 图集坐标、原生缩放和逻辑画布；不能以 DD 的 1024×576 为默认。当前 START 中一些图集坐标超过图片存储宽度，需要继续追踪原生资源处理／绘制路径。
4. 04 的原生处理调用 427F60，涉及已读记录，不能仅当作 DD 的普通历史追加操作。03 检查点也需要独立的元数据及已读状态核对。
5. 38 脚本切换先进入宿主等待流程，39 使用不同模式；需要实现各自的重置和加载效果后才能进入原版 WIN_SIZE、标题与正文。
6. 接入 DM 的音频、影片、正文控制、存读档等宿主；未实现前，Android 明确提示当前版本尚不可启动。

原生启动／对照画面尚未进行。本轮不扩大先前仅针对 DC3DD 隔离副本的动态采集授权。
