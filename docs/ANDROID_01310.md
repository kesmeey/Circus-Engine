# Android 0.13.10：DC3R 菜单与存档性能

安装 `build/distribution/circus-runtime-0.13.10-android-dev.apk`，可覆盖安装，保留最近游戏、配置、进度和解释器存档。原版存档导入沿用 [0.13.9](ANDROID_0139.md)。

## 修复

DC3R Unity 过去每保存一次，都会重新读取并完整校验所有 102 个槽位，仅用于更新菜单上的日期与台词。剧情回看历史也在存档中，因此游玩越久、保存越多，重复读取量越大。本地原版脚本推进 1,000 句后，每个测试存档约 2.35 MB；102 槽每次保存要重读约 240 MB，并反复分配状态字节数组。

现在自己的保存完成原子写入后，只更新该槽的菜单元数据。启动或恢复时，按文件长度与修改时间复用元数据；检测到替换的文件仍完整校验。真正加载剧情存档始终检查完整校验和，不使用菜单缓存绕过校验。快速存档仍独立保存，不占用编号槽位。

其他优化：

- 读取 Unity 贴图时，头部和全部像素块共用一次文件打开，完成或出错都关闭句柄。原菜单贴图 `advmenu_chip` 从 23 次打开减至 1 次；保存页 `save_back`／`sl_chip` 合计从 33 次减至 2 次。纹理缓存上限和像素数据不变。
- 菜单只保留 256×144 的预览，暂存像素从 2.25 MiB 减至 144 KiB；需要保存或后台恢复快照时才压缩 PNG。同一预览复用已编码字节，编码后释放位图。缩略图缩放算法不变。
- 回看状态压缩增加 32 KiB 缓冲，减少每个字段触发的原生 zlib 调用。回看、回退、变量和原有保存格式不变。
- 通用存档创建缩略图后立即释放其临时全屏预览，减少后台保存时等待垃圾回收的位图。

## Android 对比

Android 35 x86_64 模拟器、256 MiB Java 堆上，使用同一份旧版原脚本存档，含 1,000 条实际对白历史，分别预置不同数量的槽位。通过原版菜单选择保存并确认，比较后两轮正常保存的平均处理耗时；这两轮没有提前创建菜单快照。

|已有槽位|0.13.9|0.13.10|
|---|---:|---:|
|1|72 ms|45 ms|
|10|170 ms|48 ms|
|102|1,159 ms|49 ms|

102 槽条件下约减少 96% 的处理耗时。这是原脚本、Canvas、存档读写路径的工作线程基准，脚本时间及音频完成由测试推进，不包含手势耗时、原版等待演出和整机显示延迟。资源使用精确范围包回放；手机 SAF 文档提供器与硬件性能会影响实际速度。首次菜单仍需加载和解码贴图，不能据此承诺所有手机无掉帧。

证据位于 `build/dc3r-menu-0140/`：`baseline-android-1000.txt`、`fixed-android-1000.txt`；桌面原版文件对照位于 `baseline-userpath-1000/`、`fixed-userpath-1000/`。纹理字节及句柄对照在 `build/dc3r-texture-0140/`。这些包含本地游戏的测试数据不打包或上传。

## 兼容验证

- 997 项 JVM／Android ART 核心断言通过；Canvas 7 项像素契约、484 项遮罩比较通过。
- Android 原版菜单流程 24 项检查通过，剧情与保存页的 5 张前后截图逐像素一致。
- 独立存档回归 23 项检查通过：覆盖、快速保存、文件替换／删除、损坏校验、旧版菜单与剧情存档、1,000 条历史和历史回退。旧版 4.6 MiB 菜单快照仍可恢复和继续保存。
- 原版标题、菜单、保存／读取、设置、回看、CG／场景／音乐鉴赏流程检查通过；并非全路线再次验收。

复现工具为 `UnityMenuPerformanceAudit`（PC）、`UnityMenuPerformanceInstrumentation`（Android）、`UnitySaveCacheAudit` 与 `UnityTextureIoAudit`。所有测试使用隔离输出目录，原游戏和 PC 存档只读；重复的测试槽位在保存证据后清理。
