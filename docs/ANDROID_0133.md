# Android 0.13.3：DC2PC 原版进度导入

安装 `build/distribution/circus-runtime-0.13.3-android-dev.apk`，直接覆盖安装。
保留 0.13.2 的菜单／存档性能修复以及双指点按操作。

## 使用方法

1. 将电脑游戏目录中的整个 `AdvData/SaveData` 文件夹复制到手机同一游戏目录的对应位置。
2. 打开解释器，在 DC2PC 卡片上点“更多”→“导入原版进度（DC2PC）”。
3. 查看新增标记数量，点“合并导入”。
4. 重新启动该游戏，在原版标题和鉴赏菜单查看进度。

导入读取 `AdvData/SaveData/system.dat`。当前支持 `dc2pc-5769` 的 D.C.II P.C 系统存档。
当前版本不支持 DC1、DC2DM、DC3DD 或 DC3R 的原版存档导入；这些游戏仍可正常使用解释器自己的存档。

## 支持的内容

- 已验证的通关／解锁标记。
- CG 与场景鉴赏的解锁标记，包括已存在的差分记录。
- 与手机进度合并：电脑未解锁的项目不会清除手机已解锁项目。
- 重复导入不会重复修改进度。

数量是内部标记数量，不代表路线数、CG 张数或菜单缩略图数量。
只读取当前选中游戏内的系统存档，不扫描或自动选择备份存档包。
源文件没有游戏标识或校验和，因此需要由游戏目录的 MES 版本配合判断；不要把其他游戏的同名文件放进该目录。

**剧情槽位 `dc2pcNN.dat` 尚不转换。** 原版 LOAD 菜单中不会因此出现这些槽位，也不能从它们保存的那一句继续。
导入预览会列出检测到的原版槽位数量并说明这一限制。通关／鉴赏导入不会把所有文字标成已读。
手机已有剧情存档、姓名、音量、语音开关等设置保持原样。

## 保存与备份

原游戏目录保持只读。合并结果写入解释器现有的应用私有 `progress.dat`，与正常游玩共用同一游戏标识。
如果手机已有系统进度，替换前会保存一份 `progress.before-native-<时间>-<唯一标识>.dat` 备份。
先编码并验证完整结果，再备份和原子替换；预览与执行之间源文件变化会要求重新预览。
损坏的手机进度或不符合已验证格式的原版文件会拒绝导入，不会作为零进度覆盖。
没有新增标记时不写文件，也不额外生成备份。
如果检测到旧版手机 `progress.dm` 尚未迁移，会提示先启动并退出该游戏；完成旧进度迁移后再导入，避免遗漏手机原有记录。

备份保存在应用私有目录，因此不要卸载应用或清除应用数据。

## 格式依据

本地原 EXE 的 `0x404C67` 将 `0x52B3B0` 开始的 `0xCF0`（3312）字节写入 `system.dat`，
变量读取器 `0x41A300` 对应下列持久 bank：

| 文件偏移 | bank | 字节数 | 本次处理 |
|---|---:|---:|---|
| `0x70` | 100 | 100 | 仅合并 `0..19, 21, 28, 29` 中的已解锁标记 |
| `0xD4` | 97 | 1500 | CG 标记 |
| `0x6B0` | 98 | 1500 | 场景标记 |
| `0xC8C` | 95 | 100 | 保留手机语音设置，不导入 |

bank 100 的其他字段包含标题偏好、临时状态和静音设置，不能把整个区块覆盖进去。
导入字段要求值为 0 或 1；长度、版本和目标宿主不匹配均拒绝。
原版剧情槽位为 11040 字节，加载器 `0x4252D0`／`0x424FF0` 还恢复脚本检查点、变量和 UI／场景状态；
将槽位的脚本名直接当作续读入口不能还原完整存档。

测试使用自造文件验证格式和合并，再通过独立 Android 测试目录读取本机原资源验证导入。
原版存档、脚本与测试画面不会打入 APK 或源码包。

## 验证结果

- 631 项 JVM 核心断言、47 项 Python 测试通过。
- Android 15 模拟器通过 41 项原版进度导入检查：备份、重复导入、旧进度迁移保护、源文件变化、损坏目标拒绝、保留手机槽位及读档后保留解锁。
- 使用本机原版系统存档，导入后重启解释器，原版 CG 列表可打开大图；音姬场景鉴赏可选择条目并进入原版对白。
- 补齐 DC2PC `0x58` 列表标题及 `pc.command(7)` 场景列表绘制，包括日期、标题字号与描边。沿用现有列表存档格式。
- Android ART 核心测试、7 项 Canvas 像素约定、484 项遮罩像素比较以及 25 项 DC2PC 启动／正文／回看／存读档回归通过。

导入流程测试模拟媒体完成事件；普通运行回归另检查实际音频启动。以上不是手机全路线或全部鉴赏条目的认证。
已知缺口：本机这版 DC2PC 的 Scene「other」分类会进入 `sce_other.MES@0xA1B` 的未支持记录 `0xBF`，目前仍不可用；该路径与解锁进度无关。本次确认可用的是音姬（otome）分类及其场景跳转，没有将未知记录跳过。
本机测试记录位于 `build/android/verification-0133/`。
